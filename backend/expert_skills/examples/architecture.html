BACKEND ARCHITECTURE REFERENCE

预约管理，清晰的系统边界。

此案例展示专家的架构产出形式。它是参考方案，不提供已连接数据库的假操作。

请求与数据流

预约表单→身份认证与输入校验→预约服务→数据库事务→返回实际预约

API 与访问范围

端点行为权限
POST /api/appointments创建预约，校验时间冲突登录用户
GET /api/appointments查询个人预约仅当前用户
PATCH /api/appointments/:id幂等取消预约预约所有者

数据模型与一致性

appointments 包含 id、user_id、slot_id、status、created_at 和 updated_at。外键维护引用完整性，唯一约束限制有效时段重复预约。

创建预约在一个事务内完成；并发冲突返回 409。取消保留历史记录。列表查询始终使用当前登录用户身份，不能依靠客户端传入的 user_id 决定权限。

验收清单

创建后刷新仍可查询；取消后状态持久保存；重复请求不重复写入；无权限用户不能读取或取消他人的预约；数据库和 API 错误在表单中准确反馈。
