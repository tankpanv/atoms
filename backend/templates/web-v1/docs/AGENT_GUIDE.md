# 默认模板编写规范
## 先实现完整产品
演示优先：外部 AI/支付/邮件等依赖未配置时记录配置 TODO，保留真实适配器并实现明确标注 simulated:true 的演示适配器；继续其他功能，不停止整项任务。难以修复的局部问题允许延期或绕过，说明缺失范围；通过真实构建、页面启动和可用演示流程后交付，不能把模拟宣称为真实服务验收。未完成任务用 deferred 并记录原因/配置步骤，推进依赖任务。
以 .atoms/PLAN.md 的明确需求为准。先确定共享类型和核心数据流，再集中编写一个端到端功能的页面、领域逻辑、必要 API 和测试；简单需求通常 1–2 批实现。不要重建脚手架、改已有工具版本或反复安装/通读模板。交付不是显示一个静态壳。
## 前端
预览支持普通 HTTP 和沙箱环境。安全上下文 API 必须检查能力；生成标识符用 src/lib/id.ts 的 createId，不直接依赖 crypto.randomUUID。平台会执行实际 JavaScript 启动检查，即使用户没有启用完整浏览器交互验收；构建和 API 成功不能替代页面正常渲染。
默认前端完整技术栈为 React / TypeScript / Vite / shadcn-ui / Tailwind CSS；组件真实预置于 frontend/src/components/ui，@/ 指向 frontend/src。先遵循 frontend/README.md，在根 DESIGN.md 明确 Direction & Layout、Tokens、Shared Patterns & States、Media 四部分；存在则沿用。设计与业务可同一批工具调用按顺序写入，不能反复设计或增加独立审查循环。
App.tsx 是路由外壳，默认 / 路由为 pages/Index.tsx；保留 BASE_URL / 发布页 <base> 对应的 basename，不能把平台子路径发布路由改成根路径。pages/ 放业务页面，lib/ 放领域算法和 API 访问；按实际职责添加 components/hooks，不为简单需求制造层级。样式在 index.css 或相邻模块；根据需求设计独特视觉、排版、间距、响应式和可访问交互。选择符合产品调性的具体字体并设置本地回退，外部字体加载失败仍可正常显示。
每个明确按钮实现真实行为，包含加载、成功、空状态和错误反馈。关键输入/按钮/反馈设置稳定 data-testid，浏览器检查实际输入和正确/错误结果，不能只断言容器可见。
## 后端（仅 fullstack 模板）
保持模板公共接口 connection() / initialize() / database_schema() 及主入口、代理、部署配置；在 initialize() 扩展业务表，不为了业务重命名基础函数或重写整个工程。
FastAPI backend/app/main.py 组合入口；API 路由 /api/*，在 routes.py 扩展，services/ 放复杂业务，db.py 提供 PostgreSQL 连接事务。表在 initialize() 创建，版本化迁移需显式执行并保留旧数据。SQL 必须参数化；只能访问本项目 Schema，不能访问平台 public 表或将数据库凭据放入前端。
项目 Schema 和独立应用角色由平台连接器创建，APP_DATABASE_URL/APP_DATABASE_SCHEMA 仅注入服务端。每请求独立连接和事务，成功提交、异常回滚，search_path 仅本项目和 pg_catalog。使用 psycopg dict_row，SQL 参数用 %s；自增主键使用 GENERATED BY DEFAULT AS IDENTITY，幂等写入用 ON CONFLICT，不能使用 SQLite 专用语法。对输入使用 Pydantic schema，返回正确状态码；有账号/隐私要求必须真实鉴权和按用户隔离，模板健康检查不代表已有鉴权。
前端 api<T>(path, options) 使用 BASE_URL + api/ 同源请求；服务端路径 /api；Vite proxy 使用 BASE_PATH + api 精确前缀，不能拦截整个 /api/runtime 预览网关。API_PORT 由平台启动后端再注入。
## 验证与交付
先检查与需求相关的实际入口、导入/导出、前后端接口、调用链、数据流、持久化和错误处理，再执行 npm run build 的真实编译与类型校验。当前生成或修改代码可编写、更新和运行相关文件/用例的局部单元测试；最终不统一运行套件或使用历史单元测试结果，不因过期断言反复重写正确业务。最后启动当前源码的真实前后端，通过 HTTP/API 和可用的浏览器操作验证完整核心链路、错误状态及数据回读；首页可见或构建通过不等于业务完成。检查失败先区分错误步骤与真实业务缺陷，修复具体问题，重复失败时切换诊断视角、提出竞争假设并执行最小判别检查，不因失败次数直接终止，不另建无关源码审查循环。更新 README 的业务操作、真实校验及部署限制。
不需要后端的展示/本地小游戏用 web 模板；账号、共享数据、跨设备、密钥和服务器计算用 fullstack。用户明确指定的栈、版本或数据库优先，不能默默替换。沿用已有项目和会话检查点。
## 环境
Node 22；npm workspace 的 node_modules 在根目录（不要误判 frontend/node_modules 不存在为缺依赖）。React 19 / TypeScript 5.7 / Vite 6 / Vitest 3，使用 package-lock.json 固定真实安装版本。Python 3.12 / FastAPI / PostgreSQL 项目 Schema；Python/pip 使用项目独立 .venv，新增依赖写入 backend/requirements.txt，构建/预览自动安装到 .python-packages。不要改装到 /tmp 或其他源码目录。
一键生产部署 sh deploy.sh：纯前端 Nginx，全栈单容器 FastAPI 同源提供静态页面和 API，PostgreSQL 持久卷。平台发布目前只发布静态资源；全栈必须使用 Docker 部署，不能把 MinIO 发布声称为后端上线。
