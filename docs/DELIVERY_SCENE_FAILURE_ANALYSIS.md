# 24 点任务验收失败的根因与修复

受影响任务：`33ebfaae27174fdc9016877a0056fa31`，原构建任务 `57e8be7c-265d-44a0-a28f-d711c3c3a172`。

源码构建和 12 个 Vitest 测试已经成功。之后平台观察页面，让模型把规划中的文字验收步骤转换为浏览器操作 JSON。失败发生在平台生成验收场景的阶段，并非游戏构建阶段。

原来的两次 TEST 调用使用 `deepseek/deepseek-v4.1-flash`。两次都返回 `finish_reason=length`，`completion_tokens=2000`、`reasoning_tokens=2000`、正文长度为 0。单次调用的 2,000 token 输出预算被思考全部消耗，JSON 根本没有生成。第二次仍使用同样的小预算，因此无法恢复。之前提高构建任务总 token 限额不会改变这个局部写死的输出限制。

官方协议说明：https://openrouter.ai/docs/guides/best-practices/reasoning-tokens 。多数提供方将思考和可见输出合计计入 max_tokens；exclude 只隐藏思考，不能解决预算耗尽。

修复内容：

- 场景生成采用低思考强度，初次输出预算 8,192；截断时下一次改为 16,384，重新生成完整场景，不接续半截 JSON。构建任务与演示阶段的已有预算仍会限制实际请求。
- 记录 finish_reason、思考用量、正文长度、输出片段和校验错误；失败也持久化诊断，不能只显示笼统的解析错误。
- 页面观察补充可见答案、反馈等非输入控件，以及其直接子节点；浏览器断言失败也提供实际页面文本和节点证据。
- 真实浏览器的选择器/文案不匹配最多允许两次场景纠正（分别观察成功/拒绝反馈），不触发反复改写业务代码。真实页面异常或失败 HTTP 响应继续交给实际工程修复；真实功能缺失仍返回 missing_functionality。
- 缓存的失败场景被重新生成。24 点游戏必须通过真实参考答案提交、正确结果文本断言、错误输入提交及错误反馈文本断言；仅断言容器可见的弱场景会被拒绝。
- 单次解析阶段最多两次模型请求，浏览器证据纠正最多两次，因此最多六次场景请求，且全部经过既有总预算包装。原有模型网络重试与计费幂等约束继续生效。
- 镜像构建新增强制场景/模型流回归检查，阻止这类问题再次随镜像发布。

原用户项目已通过真实浏览器的 11 项操作/断言：随机参考答案提交成功、错误输入拒绝、换题清空输入/参考答案、四张牌保留；无页面异常、无失败响应。也通过 Playwright MCP 在真实预览代理地址再次验证。原用户业务源码未修改，历史失败日志保留。

回归测试：83 项通过。镜像内强制检查：4 项引导合同测试和 26 项场景/流式模型测试通过。

真实模型复测：同一款 DeepSeek，3 次模型调用、19,791 个真实 token、费用 $0.004639124。场景根据真实成功/拒绝文案纠正后，8 个动作和断言全部通过，无页面异常或失败 HTTP 响应，业务文件未修改。证据保存在 `scene-feedback-model-evidence.json`；最早的弱场景被识别后已新增拒绝测试，未将其作为最终通过证据。
