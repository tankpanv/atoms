## MetaGPT 中可借鉴的具体机制

[工程师提示](https://github.com/FoundationAgents/MetaGPT/blob/11cdf466d042aece04fc6cfd13b28e1a70341b1f/metagpt/prompts/di/engineer2.py) 对简单需求允许直接执行，要求观察上次动作避免重复错误、合并同一文件修改并遵循设计接口。不能照搬其中所有按文件生成步骤，否则本平台可能增加调用数。

[Planner](https://github.com/FoundationAgents/MetaGPT/blob/11cdf466d042aece04fc6cfd13b28e1a70341b1f/metagpt/strategy/planner.py) 把目标、上下文、当前计划和当前任务分开组织；工作记忆按任务清理。这里采用持久合同与每轮聚焦指令，压缩后重新注入当前错误，不依赖模型重新通读项目恢复记忆。

[Engineer](https://github.com/FoundationAgents/MetaGPT/blob/11cdf466d042aece04fc6cfd13b28e1a70341b1f/metagpt/roles/engineer.py) 与 [WriteCode](https://github.com/FoundationAgents/MetaGPT/blob/11cdf466d042aece04fc6cfd13b28e1a70341b1f/metagpt/actions/write_code.py) 明确使用设计、任务、旧代码和错误上下文构建 CodingContext。这里采用可校验的模块导出/调用者契约，减少跨模块导出名称和参数猜测。

## 已实现的执行流程

1. 只规划明确要求与核心正确性；技术假设不变成产品扩张。简单产品集中实现，不按辅助函数造模块。
2. 简单前端计划的纯初始化前置任务合并进依赖它的产品任务，保留所有需求和文件，避免初始化需要后续功能验收的死锁。复杂后端项目保持其依赖计划。
3. 空项目且已明确 Vite React TypeScript / frontend 时，执行器运行真实 CLI 初始化并把结果和文件清单交给模型，把实际模板配置/入口全文一起交接，不占额外模型读取循环，并登记真实初始化证据。既有源码、其他栈不自动初始化。
4. 任务聚焦指令和当前修复目标在每轮压缩后重新注入，保留最新工具结果/参数错误为最后消息。模块接口只携带与当前任务相关的部分。
5. 安装成功才保存依赖声明/lock + 实际安装标记；声明、安装标记变化或安装失败重新执行。默认初始化构建入口不再每次安装；自定义显式 install/ci 命令保持原意。
6. 仅在本次 run 内复用相同源码/配置的成功构建；失败不缓存，shell/初始化会使构建证明失效。测试、HTTP 和浏览器仍执行，不缓存用户交互结果。
7. 配置/计划中的演示场景作为提案，先观察真实页面，再生成一个与控件及运行数据匹配的小场景，真实 Chromium 执行具体断言，保存合同供续建复用。即使提案 JSON 合法，也不能把固定答案强加给随机题目。新增版本键使旧场景重新核验，不让开发模型为了平台元数据重复写项目。
8. 场景生成服务故障/两次不可解析输出明确保留检查点并报告，不把供应商失败归为源码缺陷；实际缺少目标功能继续修复。实际生成场景断言失败仍必须修复，不能以页面打开替代验收。断言超时不再因缺少成功报告字段而被误诊为空页面。
9. 相同源码/启动配置直接复用运行进程；源码变化自动重启全部必要服务。退出/取消清理整组子孙进程，即使 shell 父进程已退出。新 worker 启用 Docker init 回收孤儿，并设置与 CPU 配额相符的 CPU affinity，让 Node availableParallelism 看到实际可用核数，避免测试池按宿主机核数过量启动；旧容器在下一次排队或空闲时升级，正在运行的任务/有效预览租约不强制中断。

10. 浏览器提供 fill_from_text 和 assert_value：从实际可见的参考答案填写输入、校验换题后清空，不为测试改成固定生产题目。随机应用可在一个场景完成真实正反例验收。
11. OpenRouter 返回加密端点/地域锁定错误时，只恢复一次：保留所有可观察消息、工具调用和真实回执，移除无法迁移的加密推理块，更新 cache epoch/session_id 并创建新的幂等计费请求。第一次拒绝仍记录为 rejected，成功请求正常结算；没有可用端点仍如实失败。依据 [OpenRouter 缓存与粘性路由文档](https://openrouter.ai/docs/guides/best-practices/prompt-caching)，session_id 是路由粘性键。该机制重新选择服务允许的端点，不绕过地域权限。

原阶段预算、人工停止、账户余额和真实计费保持生效；超正常阶段预算后转入独立限额的收尾，仍要求真实可演示；收尾自动取构建 token/轮数配置的一半，默认最多 7500000 tokens、60 次模型调用/60 轮，达到任一上限保存检查点并停止。部分验收的演示版本与完整 COMPLETE 保持区分。

## 验证

回归测试覆盖：缺失/文字演示合同、不成功断言不能交付、供应商错误不触发改源码循环、初始化依赖合并、依赖缓存失效、相同源码运行进程复用与源码变化重启，以及原有持久会话、工具参数、预算和停止逻辑。

独立真实测试的用量、时间与容器进程结果记录在 `agent-workflow-verification.json`。它是实测记录，不保证任意需求或任意供应商延迟都在 2 分钟完成。

实测：旧任务最终 142 次结算请求后被用户停止；独立新建同类任务 19 次请求、410.10 秒形成可演示版本（还未达到官方两分钟）。另一个新建测试遇到供应商 403，后续真实续建已保存演示版本；全部拒绝/结算均保留。最终随机玩法用 Playwright MCP 验证 4 次刷新不同初始牌、8 局参考答案提交/错误拒绝/换题清空，并在应用查看器 iframe 内确认真实页面。82 项回归中 81 项通过、1 项需要独立 CLI 下载烟测而跳过；已另外完成实际 CLI/Chromium 构建试玩。最终发布镜像的 9 项场景回归全部通过。
