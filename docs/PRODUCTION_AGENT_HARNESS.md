# 系统性交付与执行决策（2026-10-06）

当前外部依赖和交付策略以 [演示优先交付](DEMO_FIRST_DELIVERY.md) 为准：不因缺配置停止整体开发，允许明确模拟和延期，优先交付真实可启动的演示。下述较早的严格完整验收/配置停止描述保留为历史背景，已被该策略取代。
## 案例与根因

项目 `f70ceb36-e7c8-4668-8e29-c6458c9d451a` 要求真实 AI 穿搭生成，任务 `c9b10cbd-5468-4ade-968d-aa35f3077692` 共记录 1042 条步骤，68 次 PLAN 模型调用，66 次 IMPLEMENT/TEST 阶段切换。真实生成接口明确返回缺少 `OPENAI_API_KEY` 的 503；额度查询成功，生成和扣减额度成功路径没有通过。任务最终被标为 done，但实际只交付了可演示版本。

问题不是单纯模型能力不足：规划假定未绑定的业务 AI 服务可用；开发反复诊断相同配置事实；接口请求编码与成功证据关联容易遗漏；交付允许在核心能力未通过时降级为演示。平台智能体模型网关凭据与产品业务服务凭据有独立的用途及权限，不能互相假定已提供。

## 当前机制

- 新 Web 软件计划必须包含 `system_contract`，缺失则反馈模型修正，不能悄悄绕过。旧检查点保持可读取。合同包括覆盖全部需求的用户链路、接口请求编码和字段、生产者与消费者、2xx 成功响应断言、外部依赖实际绑定与探测、不变量和完整开发顺序。简单页面不强行增加 API 或后端。
- 开发每轮收到当前源码的任务状态、具体需求目标、成功证据、其他检查及验收缺口，并重申系统合同。先探测风险最高的依赖并打通真实纵向流程，再批量完成其他模块；集中检查调用方、编码、路由、数据流和状态变化。
- API 成功合同必须有具体返回值或集合/字段/类型约束。实际执行器支持 `expect_schema`：字段、类型、每项结构、数量、长度、枚举和数值边界；不执行任意表达式。对完整真实响应校验后保存结构化证据，避免较大的图片响应因日志截断失去有效证明。
- 构建、健康检查和预期 4xx/503 不能完成核心成功需求。新合同任务标记 done 需要当前源码的成功证据；最终交付逐项检查接口成功合同及用户链路覆盖，仍须启动真实服务并检查核心业务。新合同核心缺口不能自动降级成可演示交付。
- 重复失败触发竞争假设、反向因果追踪与判别检查，不因累计失败次数终止。独立诊断按源码、任务状态、真实结果及验收缺口复用；新证据出现后才能重新诊断。改任务备注、增加证据 ID 不构成新事实。
- 若当前真实服务明确返回 503 且指出缺少具体 API Key/Secret，保存实现、证据及检查点，明确等待业务依赖配置。这不是失败次数阈值，也不会伪造结果、删除正确业务或泄漏平台智能体凭据。同接口后续真实成功会解除旧阻塞；一般超时、临时 503 或模型猜测不能确认为配置阻塞。
- 局部单元测试可在当前代码生成/修改期间辅助验证；全量单元测试不作为生成项目的最终验收标准。最终依据系统代码检查、真实启动及实际业务链路。资源和执行时间预算仍有限，预算耗尽保持未完成状态及检查点。

## 验证与边界

针对合同覆盖、空成功结果、错误路径、陈旧证据、配置阻塞解除及诊断复用做当前改动检查；真实 uvicorn HTTP 请求检查空 200、具体缺配置 503、修复后重启与成功响应合同；完整真实 Vite/FastAPI/Chromium 链路检查创建、刷新持久化、重启与最终交付。工作镜像还执行自身现有发布回归检查，这些是 harness 代码发布检查，不是生成项目的验收依据。

这些机制提高设计一致性和验收可信度，不能保证任何复杂目标一次成功。无可用业务 AI 凭据时，真实穿搭生成仍需要绑定可用的供应方。当前没有自动将平台智能体账户授权给用户生成的产品，也没有自动重跑历史付费任务；新的工作镜像在下一次任务/继续请求时使用。
