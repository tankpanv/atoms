# 预览网关与真实全栈验收

## 2026-10-04 事故定位

项目 `a701b74d87b34c46a61362e188c16fe4` 的注册返回 201，后端健康检查返回 200，数据写入 PostgreSQL 项目独立 Schema 正常。注册后浏览器请求学习队列、统计、词库时带有应用自己的 `X-Session-Token`。预览 HTML 的 CSP sandbox 产生 opaque origin，浏览器要求 CORS preflight；网关固定请求头白名单没有这个名称，请求尚未到达后端就被拦截。

验收有两个缺口：浏览器工具直接访问本地 Vite，绕过客户使用的网关、CSP、存储；场景协议失败后降级为 body 可见检查，错误地交付了未经过核心交互验证的预览。

## 修复机制

- 网关按 preflight 请求中的合法应用请求头返回允许列表，保留 Authorization，过滤 Cookie、Host、控制凭据和非法名称，限制数量和长度。保持 sandbox 隔离，不授予跨域 Cookie 凭据，不向项目转发平台控制密钥。
- 生产 Worker 浏览器检查经 `preview:8002` 访问真实预览入口。协调器只接受对应项目 Worker 凭据，并向正在运行的 Worker 验证 runtime token 后才登记路由。Docker 项目网络接入预览网关，容器重建后可重新接入。
- 浏览器同时检查页面异常、HTTP 错误和 `requestfailed`，覆盖 CORS、DNS、连接失败等没有 HTTP 响应的情况。准备网关失败不会回退为直接访问 Vite。
- 场景协议错误保留业务代码与诊断，继续修正并执行核心交互验收；不能用登录页/body 可见检查标记交付完成。该恢复流程沿用已有任务/演示修复预算，保持次数及 token 边界。
- 明确的工作区 demo 场景先真实执行，失败则根据浏览器反馈重新生成。规划建议仍通过实际页面控件定位，随机题目不硬编码答案。账号/表单场景必须验证提交后的业务读取，测试数据使用唯一标记。

## 验证

真实 Playwright MCP 在客户预览端口 8002 完成：新账号注册、读取 30 条默认单词、新增诊断词、练习推进至阶段 3、刷新保留登录及数据、退出、重新登录、错误密码拒绝。修复后没有 CORS 错误，诊断账号及其关联数据已清理。

`test_preview_fullstack` 用真实 Chromium 和本地 ASGI 服务重现 opaque-origin + 自定义认证请求头：正常网关请求成功；故意遗漏允许头时，即使页面显示了反馈，browser_check 仍然返回失败。另有路由注册凭据隔离、过期 token 拒绝、Cookie/控制凭据过滤、真实核心验收恢复测试。该测试模块已纳入 Worker 镜像构建检查。

本次为平台网关问题，无需改写客户的认证协议或业务实现。

## 通用新增需求验收机制

后续增量开发沿用需求 ID、受影响模块定位与当前源码指纹证据。旧版本通过记录不能替代修改后验收；验收聚焦受影响的用户流程和服务连通性，不逐文件重新审阅实现。

`browser_check` 增加通用 `assert_response`：selector 为项目相对 API 路径，method/status/expect_json 指定真实请求结果。响应必须来自当前项目预览入口，不能用第三方同名接口替代；新的操作与刷新不能消费以前的响应。返回给模型的网络摘要仅包含路径、方法、状态及断言标记，不保存响应认证凭据。

表单输入之后需要提交/触发并断言独立结果；输入回显和 body 可见不足以通过。全栈演示场景同时要求成功 API 断言和后续页面结果断言。持久化需求在执行指令中要求写入后重新加载并读取测试数据；客户端刷新可验证页面与服务读回，数据库跨进程持久性仍需对应的集成测试，不能由刷新替代。

等待已触发的 fetch/XHR 完成，最多 5 秒；API 断言最多 8 秒。流式 SSE 不作为永久等待项。未断言的 HTTP 错误、传输错误、JS 异常或服务退出均阻止通过；预期的 401/422 只允许对应接口、方法、状态和指定 JSON 的那一次响应，不能全局忽略某个错误码。既有 Agent 任务及演示修复预算继续生效。

通用回归覆盖：较晚返回的后端 503、HTTP 200 但业务 JSON 不正确、明确的表单拒绝、未经断言的拒绝、写入后刷新读回、旧响应不能证明新操作、只显示表单/输入回显的弱场景拒绝。这里校验真实服务和浏览器行为；不能把静态页面或模型自述当成功证据。

这些机制用于阻止已发现的失败进入“验收通过”。它们不等于对任意用户需求的零缺陷保证；需求覆盖、边界与数据库持久性仍须由对应可执行验收证明。
