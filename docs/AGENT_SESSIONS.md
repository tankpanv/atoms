# Agent 会话恢复与上下文管理

## 根因

旧版本持久保存任务计划与近期操作，但模型 messages 和 read_cache 只在单次进程内存中。发送“继续”会建立新的模型会话，并重新检索源码。任务恢复不等于模型上下文恢复，因而会重复理解和读取。现在这两层都持久保存。

## 实现

每个项目在 `.atoms/.agent-session/session.sqlite3` 保存活动模型上下文、完整对话增量事件、任务状态、操作记录、源码内容哈希及分页读取缓存。SQLite WAL 和 FULL 同步将检查点与审计事件原子提交。该目录权限 0700、数据库 0600，不加入 Agent 文件列表、项目源码快照和下载内容。

每次模型调用前、收到工具请求后、每个工具执行完毕后提交检查点。纯“继续”恢复原始需求、计划和模型上下文，不再次附加相同需求，不重新规划或初始化。进程重启也能恢复。旧任务没有历史模型对话时，迁移已有任务和近期操作记录，一次性读取必要源码；不能恢复旧版本从未保存的内容。

同一未完成计划中，已完成任务保留。工具结果是执行证据，最终验收仍针对当前源码重新运行。新增要求或附件触发新规划，但规划器取得持久项目记忆、文件目录及变化文件，不把完整源码再次塞进提示词。切换模型保留结构化记忆和工具结果，同时移除不可跨模型复用的签名/加密 reasoning。

每个文件以内容哈希检查变化，覆盖同长度修改、删除和二进制资产。读取缓存按文件哈希与分页范围保存。仅当原文仍在当前上下文中时返回短引用；原文已被压缩则返回经过验证的真实内容，避免模型只有无效缓存引用。文件变化会显式告知模型旧内容失效并删除该文件缓存。

中断发生在工具执行和结果提交之间时，恢复会补齐配对结果，标记“可能已经执行，先检查”，不会自动重放写入或命令。这防止重复副作用，但不是对任意外部系统的恰好一次执行保证。

## 自动压缩与预算

`AGENT_CONTEXT_TOKENS` 默认 512000，是活动上下文的压缩目标，受所选模型上下文窗口约束；代码会按模型窗口自适应：约 1M 上下文默认 512K，256K 级模型默认 256K，更小模型自动收缩。这个值是压缩阈值，不会把空的 512K 盲目发送给每次请求；实际请求只包含当前消息。长上下文模型默认保留更完整的跨目录源码工作集，仍可通过环境变量降低目标控制成本。批量 `read_files` 会在一次模型往返中读取接口、类型、路由和调用方；会话同时保存最近的版本化源码工作集，压缩后只要哈希未变化就可以直接继续使用，不再逐文件重读。本地估算仅用于压缩，不用于收费。超过目标时，先保留完整审计历史，再用真实计费模型总结早期决策、约束、失败、路径和下一步。活动窗口保留系统指令、原始需求、完整任务证据、源码工作集和最新完整工具组。摘要调用失败时用任务检查点整理，实际上下文长度拒绝时强制压缩后重试；不反复重试相同超长请求。

`AGENT_MAX_TOKENS` 默认 15000000 是整个执行的累计预算，和上下文窗口不是一回事。原有时间、轮数及余额控制仍生效。压缩不使任务无限运行，也不掩盖余额不足。

## 服务商缓存与计费

OpenRouter 请求传稳定的项目会话 `session_id`，压缩或切换前缀使用新缓存 epoch。Anthropic 在稳定前缀标记 `cache_control`，支持隐式缓存的模型由服务商处理。保留真实 reasoning 的原始前缀有助于连续请求；前缀变化后移除不可复用的 reasoning。

同一作业的模型请求按内容指纹持久保存计费 request ID，网络重试及进程重启复用；新的用户作业使用新 ID。所有模型调用，包括摘要，都经过现有预留、用量结算和账本链路。

用量详情展示服务商实际返回的 cache read/write tokens 与实际成本。平台积分仍按 `model_list` 已配置的输入/输出价结算，服务商缓存优惠与平台价格分开显示，不虚构命中或直接套用未知折扣。缓存依赖模型、路由、前缀、时效和服务商，不保证每次命中。缓存提高效率，持久状态保证正确性，二者互不替代。

## 用户界面与接口

编辑框提示会话已保存和“继续”可恢复，并展示压缩次数。所属项目的 `GET /api/projects/{id}/session` 提供恢复状态、估算上下文、已知文件及本地读取命中数；不返回原始私密对话。模型账单详情展示真实缓存统计。

## 验证

`backend/tests/test_agent_session.py` 覆盖重新打开数据库、请求 ID、同长度文件修改和删除、缓存原文失效、工具中断不重放、跨模型 reasoning、压缩与完整历史、私密目录隔离、二进制文件及真实文件工具停止/继续。模型流测试覆盖缓存控制、真实用量字段和上下文长度错误分类；计费测试验证真实 PostgreSQL 事务及并发。部署后另通过真实 UI/API 和真实计费模型验证继续链路。
