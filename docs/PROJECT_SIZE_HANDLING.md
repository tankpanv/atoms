# 项目大小与文件处理

项目源文件、资源和成果不再受平台原有的 25 MB 项目总量限制。大项目使用磁盘上的对象和流式传输，避免把所有文件内容重复装入内存或数据库。

## 已移除的固定门槛

| 路径 | 原限制 | 当前实现 |
| --- | --- | --- |
| 构建版本与代码索引 | 项目累计 25 MB | 大文件保存为项目内 SHA-256 对象；版本记录保存引用，索引流式计算哈希 |
| 文件编辑与工具读取 | 单文件 120 KB | 允许大文本编辑；模型读取按范围返回内容 |
| 资源上传 | 页面和接口单次 5 MB | 移除页面拦截；请求流式写入临时文件，成功后替换目标；中断保留原文件 |
| 接口验收工具上传 | multipart 文件累计 25 MB | 从项目文件句柄发送，不再限制累计大小 |
| 项目克隆 | 256 MiB 或 10,000 个文件 | 逐文件复制源文件，不再按项目大小和数量拒绝 |
| GitHub 导入 | 压缩包 50 MB、展开 200 MB 或 10,000 个文件 | 下载写入磁盘临时文件并逐文件解压，保留路径与符号链接校验 |
| GitHub 同步 | 200 个文件或累计 25 MB | 分批创建 blob 和 tree，全部成功后只提交一次并更新分支 |
| 成果列表 | 仅前 100 个成果 | 返回完整成果列表 |
| 项目和目录下载 | 在内存中组装 ZIP | 在磁盘上创建 ZIP64，再发送文件流，发送结束清理临时文件 |
| Nginx 部署配置 | 请求体 100 MB | `client_max_body_size 0`，API 代理关闭请求缓冲 |

120 KB 与 1 MiB 现在仅决定版本内容内联还是保存为对象，不是项目或文件大小上限。分页和模型输出预算仍然控制单次展示量，不阻止文件保存或项目构建。

## 版本对象与兼容性

大文件和超过内联预算的文件保存在项目工作区 `.atoms-snapshots/`，相同内容按哈希复用。SQLite 缓存记录源文件和对象的状态，重复构建无需再次复制未修改的大文件。对象目录不进入源码索引、下载、克隆和 GitHub 导出。

旧版本的文本和 base64 文件仍可恢复。新版本恢复前先暂存所有文件并校验对象完整性；缺失或损坏的对象不会触发当前源码删除。文件与目录之间的重构也会预检，防止覆盖未纳入版本的私有文件。

**备份必须同时包含数据库和持久化工作区卷，包括 `.atoms-snapshots/`。** 单独备份数据库不能恢复新版本的大文件。删除项目时随工作区一起删除这些对象；历史对象在项目存续期间保留。

项目容器在没有运行任务时，于显式构建、命令执行或恢复操作中采用新的 Worker 镜像，即使浏览器仍持有预览租约，也不会继续使用带有旧限制的空闲容器。

## 验证

- `backend/tests/test_project_snapshots.py`：32 MiB 文件版本、索引、恢复；大文本编辑和语法检查；旧版本兼容；对象损坏保护；257 MiB、超过 10,000 文件的克隆；上传中断保护；ZIP 下载清理。
- `backend/tests/test_github_project_size.py`：超过 200 个文件与 25 MB 的批次同步；超过旧展开大小和文件数量的导入，使用模拟 GitHub 传输，不发布外部仓库。
- `backend/tests/test_project_runtime.py`：真实项目 HTTP 服务接收超过 25 MB 的 multipart 上传。
- `backend/tests/live_project_limits.py`：可选部署验证，通过前端代理上传 128 MiB 文件，完成真实 Worker 构建、版本恢复、源码下载、大文本编辑和项目克隆；不调用模型，结束后清理临时用户及项目。

本次修改消除的是平台人为设置的项目文件门槛。磁盘容量、运行内存、网络超时、GitHub 等外部服务的单文件规则，以及聊天附件的格式校验和模型上下文预算仍然存在，不能解释成无限容量。

## 完整发布与运行文件

发布上下文包含已安装的 Node/Python 依赖，使用磁盘 tar 和流式 Docker 传输，不受旧快照大小门槛限制。生产数据库复制也不再拒绝超过 32 MiB 的结构导出。

开发命令和服务取消了单文件 1 GiB 的 `RLIMIT_FSIZE` 限制；真实隔离 Worker 已验证可创建 2 GiB 稀疏文件。CPU、内存和进程数量配额与文件大小处理分开。详见 [独立完整应用发布](INDEPENDENT_PUBLICATION.md)。
