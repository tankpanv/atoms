# 构建执行与演示交付

核心结果是可启动、可在应用查看器演示的项目。任务预算用于控制功能实现阶段；不是到点直接失败的开关。

## 需求规模与执行

规划阶段只按实际需求安排功能任务，新项目不读取平台初始化文档来理解不存在的源码。实现阶段复用规划观察，只有缺少精确信息时读取文件或任务清单。

根据已验证的计划计算执行规模，不增加一次模型分类调用：无后端、至多 6 项验收要求且至多 3 个任务为简单（最多 16 轮）；至多 6 项要求且至多 5 个任务为中等（最多 40 轮）；其他为复杂（最多 120 轮）。均受配置的更小轮数约束。计数包含正常阶段的模型调用；规划用量与调用次数也计入，循环轮数另行展示。

到正常阶段 token 预算的 85%、轮数/调用预算的约 80%、时间预算的 90%，或估计下一次请求可能耗尽 token 预算，转入 STABILIZE。真实扣费仍使用供应商返回的 usage，估计只用于提前切换。

## 独立的演示收尾

收尾阶段继续使用当前会话、源码、任务合同和工具，不重新规划项目。不再应用正常阶段的 token、轮数和时间退出条件；使用独立收尾预算，自动取 `AGENT_MAX_TOKENS` 和 `AGENT_MAX_ITERATIONS` 有效配置的一半（向下取整，最低 1）；默认 7500000 tokens / 60 次模型调用或修复轮数。正常阶段按需求复杂度降低轮数时，收尾仍按原配置的一半计算，不按复杂度调整后的轮数计算；不再使用独立 `AGENT_DELIVERY_MAX_*` 配置，token / 模型调用次数 / 修复轮数任一达到就保存检查点并停止，不自动再排队。压缩及场景生成调用也计入收尾用量。发请求前预留估算输入 token，并限制输出额度；真实用量最终以供应商 usage 为准，达到上限后不再请求模型。未实际通过演示检查不能标记就绪。用户主动发送“继续”可沿用源码和检查点开始新预算。收尾调用使用 STABILIZE 计费阶段，实际用量和扣费完整入库；账户余额、人工停止、模型服务可用性和资源隔离规则仍正常生效。

仅执行只读工具的收尾轮次不重复跑整套构建。修改代码后执行构建、已配置测试及实际启动检查；出现问题将具体输出反馈给 Agent 修复，不能删测试、改成空页面或编造检查通过。

- Web：深度/高级档构建成功、所有必要服务就绪、真实 Chromium 页面正常，并通过可执行核心场景的具体断言。普通档以真实构建、服务启动、JavaScript 首屏和可观察演示页面为交付门槛；除非用户明确要求 API，不逐接口跑验证矩阵，缺少外部依赖记录 TODO。配置中的 demo 或计划中的 delivery_checks 作为深度/高级验收提案，执行器先观察实际页面控件，生成并保存可执行场景；不会要求开发模型为了元数据反复重写项目。抓取控制台错误、失败网络响应和截图；拒绝空页面、仅 body 可见的场景。
- CLI/library：执行真实 test 命令（工作区配置优先，计划命令为后备），必须成功。执行输出在应用查看器展示，可打开终端再次运行。
- HTTP service：必须启动并通过真实 HTTP 检查。

Web 场景示例：

```json
{
  "demo": {
    "path": "/",
    "actions": [
      {"action": "click", "selector": "#add"},
      {"action": "assert_text", "selector": "#count", "value": "1"},
      {"action": "click", "selector": "#reset"},
      {"action": "assert_text", "selector": "#count", "value": "0"}
    ]
  }
}
```

深度/高级完整交付必须通过实际演示检查，随后仍执行原需求验收与独立代码复核。普通档可在真实构建、服务启动和页面首屏通过后进入 PREVIEW_READY；构建通过不能单独触发交付，页面启动检查仍是必需项。

## 结果与续建

演示检查通过后保存版本，状态 PREVIEW_READY，项目 ready；应用查看器自动启动预览。保留尚未逐项验收的任务和原始需求，`completed` 不会被改成 true。结果提示“演示版本已就绪”及“下一步可优化”，不会宣称所有功能已经验收。发送“继续”复用原计划、源码观察和会话，深化原需求。

实时界面显示规划用量、正常任务 tokens/轮数/模型调用以及单独的收尾 tokens/轮数；会话状态保存这些计数。规划与收尾的实际供应商账单不能通过切换阶段绕过。

## 验证

真实模型独立测试项目：`3f947622-3b04-4e5c-8ea6-9d55daa1c704`；仅该隔离测试 worker 的正常轮数设为 1，正常生产配置未改。PLAN 实际 2 次调用 / 6,719 tokens；STABILIZE 实际 7 次调用 / 65,247 tokens。数据库均 settled，分别扣费 0.00703450、0.02355930 积分。实际 CLI 初始化、构建与 3 个 Vitest 交互测试通过；Chromium 验证标题、0→1→0 流程，PREVIEW_READY 交付。Playwright MCP 在应用查看器的隔离预览 iframe 再次点击，确认相同结果。

此测试不是速度基准：正常轮数故意极低，用于验证超预算交付和真实计费；首次 CLI/依赖安装也包含在运行中。随后改进了简单需求分类（计数器 4 条要求、2 个任务归简单）、减少强制读取，以及跳过只读收尾轮次的重复构建。

自动回归覆盖真实执行报错后跨 token/轮数预算修复、独立计数、人工停止、空白/错误页面拦截、具体演示场景合同、原任务进度保留、原有工具参数及计费事务。外部模型/账户/基础设施失败必须如实呈现，不能伪装为演示成功。
