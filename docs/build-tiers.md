# 构建档位

首页和构建页可选择普通、深度、高级，默认普通。首页记住本机上次选择；项目在提交需求后保存档位，后续消息不指定时继承项目档位。选择只影响下一次提交，不改变已经排队或执行中的任务。

| 档位 | 范围与设计 | 验证 |
| --- | --- | --- |
| 普通 `normal` | 优先完整实现前端目标、视觉结构、交互状态和可启动演示；后端保留真实接口与实现，不让未配置外部依赖阻塞预览 | 源码结构检查、真实构建、服务启动、页面首屏/核心演示状态；除非用户明确要求 API，不逐接口跑验证矩阵 |
| 深度 `deep` | 普通标准 + 与目标有关的遗漏细节、边界、状态反馈、持久化、模块与接口设计 | 核心路径 + 相关关键错误/边界、状态保持 |
| 高级 `advanced` | 深度标准 + 有理由的必要扩展、完整用户旅程、跨模块契约、可靠性与安全/访问体验 | 完整路径 + 必要扩展、关键跨模块风险与回归 |

所有档位尊重用户范围、技术栈和禁止事项。不会仅因为档位更高自动添加支付、团队、后台或无关业务。简单需求仍然使用简单架构，不要求逐文件复审或反复验收。

普通档生成或修改代码时可以为当前具体错误做局部诊断，但不为了验收批量创建/运行单元测试；没有明确 API 验收要求时不向模型开放 `http_request`，明确要求时最多执行一次代表性探测，未配置或不可用的服务记录 TODO 后继续前端演示。默认 web 模板的锁定 npm/Python 依赖由 worker 镜像预热并按指纹复制到项目，不重复联网安装。最终门槛仍是当前源码的真实构建和实际页面启动，不把首页 HTML 或模拟结果冒充完整后端验收。

## 预算

token 上限及轮次/模型调用次数上限均在 `AGENT_MAX_TOKENS` / `AGENT_MAX_ITERATIONS` 的基础配置上乘以档位倍数，默认普通 1、深度 2、高级 3。可分别用 `AGENT_BUILD_NORMAL_MULTIPLIER`、`AGENT_BUILD_DEEP_MULTIPLIER`、`AGENT_BUILD_ADVANCED_MULTIPLIER` 配置正整数倍数，重启服务生效。

这些额度按每次用户消息创建的任务独立计算，不累计项目历史对话。规划默认与实现共用本次任务额度，已用量按供应商 usage 计数；`AGENT_PLANNING_MAX_TOKENS` 留空时不附加较小的规划上限，填写正整数时才额外限制规划。同一任务自动恢复保留预算计数，用户发新消息或“继续”创建新任务并重置预算。

基础配置 15000000 tokens / 200 轮时，普通为 15000000 / 200，深度为 30000000 / 400，高级为 45000000 / 600。token 基础值保留最低 10000，轮次最低 1；不再对轮次施加隐藏的 240 上限。演示收尾独立预算取档位生效后上限的一半，分别为 7500000 / 100、15000000 / 200、22500000 / 300。接近上限判断也使用档位生效后数值。上下文窗口和超时时间保持各自配置。

检查点记录基础上限、倍数、档位与实际生效上限，避免重复乘倍数；更高预算不要求消耗更多轮次，任务仍应在完成真实验收后立即结束。

## 链路

`ProjectCreate.build_tier` → `projects.build_tier` / 用户消息 → `agent_jobs.build_tier` 快照 → `make_plan` → `requirements.json` / 任务账本 → `run_agent` → 实际功能验收。

`MessageCreate.build_tier` 可省略（继承项目），显式选择会更新项目默认档位。克隆保留档位。旧项目、消息和任务迁移为普通。

策略统一在 `backend/build_tiers.py`。规划、执行和场景验收均接收对应策略；计划记录档位及策略版本。规划新增的 `origin` 可为 `explicit`（明确需求）、`detail`（补充细节）、`extension`（必要扩展）。补充项要求说明 `rationale`；只有高级允许 `extension`。所有纳入交付的补充必须进入任务和验收，不能只写在设计说明里。

规划缓存和演示验收缓存包含档位/策略版本。切换档位后发送“继续”会围绕原始目标重新规划，复用已验证源码和架构信息；同档位继续沿用有效计划和检查点。业务源码未变化且相同操作已通过时仍复用实际验证证据。

## 验证

`test_build_tiers` 覆盖 API 枚举与兼容默认值、任务快照、扩展边界、继续时保留原始目标、三档规划缓存隔离、执行真实工具及预算倍数、接近上限判断、独立收尾预算、验收策略传递。Docker 镜像构建执行此套回归。

运行 `RUN_TIER_DATABASE_TESTS=1` 可额外执行真实 PostgreSQL/API 测试，覆盖三档持久化、消息继承、任务快照不可变及无效档位拒绝；使用独立临时账号与项目，结束后清理。这项测试隔离任务分发，不发起模型请求。实际模型链路已另行用深度档网页构建验证到服务启动、浏览器按钮交互和最终完成状态。
