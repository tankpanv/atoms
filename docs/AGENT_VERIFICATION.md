# Agent 验证与停止边界

当前外部依赖和交付策略以 [演示优先交付](DEMO_FIRST_DELIVERY.md) 为准：不因缺配置停止整体开发，允许明确模拟和延期，优先交付真实可启动的演示。下述较早的严格完整验收/配置停止描述保留为历史背景，已被该策略取代。
项目 Agent 在生成或修改代码期间可以编写、更新并执行当前改动相关的单元测试，运行时明确指定文件或用例，不执行全项目套件。局部结果仅用于当次诊断，不能关联为需求通过证据。mock 可用于局部隔离，但不能冒充真实业务通过。最终验收不统一运行单元测试，也不汇总历史单元测试结果；Web/service 的自动交付不运行 commands.test，构建和启动命令不得夹带测试。CLI/library 的最终命令只运行真实产品，不使用单元测试运行器。

验证顺序按构建档位执行：所有档位先检查实际入口、模块接口、调用方和需求覆盖，再执行 Python 语法、JSON 配置及真实构建/类型检查。普通档最后重新启动当前源码的服务并检查 JavaScript 页面首屏和可观察演示状态；除非用户明确要求 API，不逐接口运行矩阵，外部依赖失败记录 TODO，不阻塞前端预览。深度/高级档再按计划验证真实核心用户链路、请求和数据回读。启动、健康检查或首页可见不能冒充深度/高级功能验收；普通档的页面启动检查也不能被构建省略。

Web 的真实 JavaScript 启动和非空页面检查必做，即使未启用完整浏览器交互工具；先确认实际页面挂载且无运行错误，再执行 HTTP/API 回读。启动检查不开放模型浏览器工具或自动执行完整业务交互。普通档没有明确 API 验收要求时不开放 `http_request`，明确要求时最多执行一次代表性请求；API 失败转为 TODO，不触发后端 API 恢复循环。独立本地检查使用普通 HTTP origin，避免 localhost 的安全上下文特殊待遇漏掉 crypto.randomUUID/剪贴板等兼容性问题；生产检查经过实际预览网关。启动策略版本参与验收指纹，旧的 HTTP-only 成功缓存不能复用。

重复失败状态随会话持久化，用于改变诊断方法，不以失败次数判定任务失败：

- 验收缺口重复出现时进入恢复诊断；同类执行错误再次出现或操作停滞时，切换诊断视角。
- 恢复循环依次从证据/合同、逆向因果追踪、最小判别实验、生命周期/不变量定位问题，保留前次方案和实际结果，不换措辞重复猜测。
- 独立诊断基于实际工具结果、当前源码、任务及证据缺口，必须提出至少两个竞争假设和各自的支持/排除条件，然后由实现模型执行真实检查、最小修复、重启及验收。诊断结论本身不是通过证据。
- 预期且通过的 4xx 是错误路径证据；历史日志不能把它误判为业务失败。服务命令的 `$PORT` 与提供给前端的 `API_PORT` 用途不同，不能仅凭变量名推断配置错误。
- 自动构建产生当前源码的真实构建证据；不代替 API/用户链路，不自动把任务标为完成。源码修改后必须补齐当前证据并关联任务。
- 同一源码和参数的失败调用只实际执行两次，之后返回原始结果，促使改变诊断或修复路径；取得其他真实判别检查的新成功结果后允许一次重试，重复读相同源码不能解锁；成功的写操作不会自动重放。
- 不因验证失败累计、检查场景失败次数或无进展轮数直接终止，不降级为首页验收。达到总时间/token/模型调用资源预算或用户主动停止时保存代码、上下文、待验证假设与检查点；不标记完成，也不自动创建重试任务。

`http_request` 发送对象 JSON、原始字符串、URL 编码表单及真实项目文件的 multipart 上传，编码必须与实际接口合同一致。

新 Web 计划必须包含系统合同，最终 API 成功条件支持具体 JSON 内容及 `expect_schema` 集合/结构约束。空的 200、健康检查或预期错误不满足成功条件。大响应在完整校验后保留结构化验收结果，不依赖被截断的日志。当前真实响应明确指出具体业务 API Key/Secret 未配置时，保存实现并等待依赖配置；该状态由事实触发，不由失败次数触发，成功调用可清除旧阻塞。完整机制与案例见 [系统性交付与执行决策](PRODUCTION_AGENT_HARNESS.md)。

修改位置：`backend/verification_policy.py`、`backend/execution_guard.py`、`backend/agent_recovery.py`、`backend/agent_checks.py`、`backend/agent.py`，以及规划和模板规范。执行器自身的回归检查验证这些边界；产品交付仍依据真实运行结果。
