# 独立完整应用发布

发布不再使用开发工作区运行后端。每次发布将前端构建产物、后端源码、已安装的 Node/Python 依赖和私有 Python 解释器打入固定 Docker 镜像。完整镜像（包含基础层）与构建上下文归档到私有 MinIO，记录 SHA-256；本地 Docker 镜像删除后可以从归档恢复。

## 环境与数据隔离

开发容器使用自己的工作区；发布容器的代码来自只读镜像，不挂载开发工作区，也不运行 agent 或编辑工具。只有该项目的 `.atoms-data` 目录可持久写入。开发环境的编辑、依赖安装、构建、还原和停止不改变发布代码。

发布数据库有独立的受限 PostgreSQL 角色、密码和 schema。两种环境共享托管 PostgreSQL 服务，但不共享项目数据表。第一次发布复制开发数据库与应用数据作为初始状态；后续更新、回退和再次发布保留生产数据，不再次从开发环境覆盖。

生产认证密钥保存在生产私有目录，更新与重启保持稳定。首次迁移旧发布时复制已有应用密钥，以保留已有会话；此后两个环境的密钥文件独立。平台数据库、agent、模型和存储管理凭据不进入应用子进程。

每个项目有独立发布网络。发布容器不受开发环境闲置回收影响，具备重启策略、健康检查和服务进程监督。

## 生命周期

发布窗口可以选择已有构建版本，默认最新的已完成版本；当前开发任务仍在构建时，也可发布已有版本。`PATCH /api/projects/{id}` 的 `published: true` 提交异步发布，返回 `publication`，可传 `publish_version` 指定构建版本号，省略时在提交时固定最新版本。不存在的版本或另一个版本正在发布时返回明确错误。

提交成功不等于已上线。`GET /api/projects/{id}/publication` 返回真实阶段、失败原因和当前线上 release ID。浏览器等待 `active` 后展示成功，刷新后可继续追踪任务。

发布从所选版本的不可变源码快照复制文本、二进制和大文件对象，在独立临时容器中按该版本的依赖声明和锁文件重新构建，再将完整源码、安装后的依赖和 `dist` 固定为发布镜像。不还原、不构建或修改开发工作区；读取快照对象之后即释放工作区锁。临时构建容器只挂载该版本的暂存目录，没有开发/生产目录或数据库、平台凭据，完成或取消后清理。

构建、归档、容器启动与 HTTP 就绪检查成功后，前端资源索引和后端 release ID 在一个数据库事务中切换。失败、中断或协调服务重启不会自动激活候选版本。旧容器保留 65 秒供已有请求完成，随后停止，历史归档保留供回退。

`GET /api/projects/{id}/releases` 查看历史。`POST /api/projects/{id}/releases/{release_id}/activate` 恢复已验证版本，先恢复镜像、启动并检查，再切换。发布窗口设置中也可恢复历史版本。

回退恢复代码与依赖，保留当前业务数据。应用升级应使用兼容的数据库迁移；代码回退不撤销业务写入或数据库迁移。取消发布关闭入口并停止容器，保留版本、数据与密钥；删除项目清理所有开发/发布容器、网络、数据库、私有文件、镜像和 MinIO 归档。

## 启动约定

默认 Vite 项目直接提供构建后的 `dist`，不启动 Vite 开发服务器。`.atoms-workspace.json` 中 `services` 的 `api` / `backend` 服务使用原启动命令、端口变量与 HTTP `ready_path`；单服务也可自动识别。自定义全栈服务器可指定生产命令：

```json
{
  "publish": {
    "command": "node server.js",
    "ready_path": "/health",
    "api_service": "api"
  }
}
```

`publish.services` 可覆盖开发服务列表。命令运行于冻结项目目录，配置 `NODE_ENV=production`、`PORT`、`APP_DATA_DIR`、私有 Python PATH、生产数据库和本地签名密钥。自定义非 Vite 应用可沿用已有启动约定。动态入口、普通 HTTP 路由和 WebSocket 均通过发布容器转发。持久文件应写入 `APP_DATA_DIR`。

页面沿用 iframe 隔离与项目 Web Storage。显式应用 Bearer 凭证可转发，平台 Cookie 和控制凭据不转发；基于 Cookie 的认证、IndexedDB 与 service worker 保留现有不透明来源限制。

旧静态发布自动迁移，前端资源来自原发布对象，避免悄悄替换为当前开发页面。旧机制没有后端版本归档，因此首次迁移冻结迁移时的后端；此后的每次发布均有完整固定版本。

## 验证

`backend/tests/test_release_artifacts.py` 覆盖完整依赖打包、超过 25 MB 的产物、源码冻结、私有状态排除、符号链接、DNS 名称和数据库身份。公开 API 回归验证不调用开发 runtime，并检查访问控制、跨域与浏览器隔离。

`.deploy/verify-independent-publication.py` 在真实 Docker / PostgreSQL / MinIO 栈创建并清理临时项目，检查发布后修改开发源码、依赖、数据库，重启/停止开发服务；新版本切换和数据/密钥保留；失败候选不影响旧版本；移除本地镜像后的 MinIO 回退恢复；隐私、取消发布、再次上线和实际浏览器访问。

2026-10-09 已完成真实栈验证：完整产物为 65,184,375 字节；失败候选保留旧版本，镜像删除后可从 MinIO 恢复并回退，生产数据与密钥不被开发修改或回退覆盖。数据库复制与初始化标记在同一事务提交，故障回滚后重试不重复复制数据。实际项目 worker 可创建 2 GiB 稀疏文件，不再受此前文件大小限制影响。HTTP 转发流式传递请求，避免上传在每一跳整体进入内存。

当天已迁移全部 20 个现有已发布项目。平台 backend、agent-service、preview 与 frontend 重建并重启后，20 个线上 release ID、镜像 ID、容器 ID、前端内容与生产密钥摘要保持一致，全部发布容器健康。只读验证脚本为 `.deploy/verify-all-published-restart.py`，结果保存在 `.deploy/all-published-after-restart.json`；临时功能测试项目与账户均已清理。

版本选择验证见 `.deploy/version-publication-live.json`：在开发状态为 running、开发文件与历史版本完全不同时，依次发布版本 1、2，省略版本号发布最新版本 3，公开页面、API 和私有依赖均对应所选版本，开发文件与状态不变。版本 4 故意构建失败后，版本 3 仍提供服务，临时构建目录、项目和账户全部清理。浏览器验证默认最新、选择旧版、新构建完成后更新默认选项并保留明确的旧版选择，以及发布中的禁用状态。发布中的其他版本请求（包括默认最新）会被拒绝，同版本重复请求复用任务。
