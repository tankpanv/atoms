# 演示优先交付（2026-10-06）

根据用户最新要求，外部依赖缺配置及暂时难解决的问题不停止整体开发。检查用于尽量定位并解决问题，最终优先交付可启动、可操作的演示，允许部分缺失。

- 真实接口确认缺少业务凭据时，记入会话的 deferred_dependencies，并继续开发。重复探测不重复添加 TODO，不触发整项任务停止。真实成功验证可清除对应 TODO；模拟成功不能清除真实配置 TODO。
- 保留真实供应方适配器，允许增加明确标注 simulated:true 的演示适配器及界面提示。实际 HTTP、数据持久化、额度和页面操作仍能验证，模拟供应方不算真实业务验收成功。
- update_task 支持 deferred，必须说明已实现/模拟的部分、缺口和后续配置或修复步骤。延期任务不被标成 done，但不阻止依赖任务继续；状态随会话持久化。
- 进入交付阶段或所有可执行任务完成/延期时，可交付 demo。完整系统合同的缺口写入 DELIVERY_TODO.md 和交付说明，不反复运行完整验收阻止演示。保留完整完成的更高标准：只有实际需求证据均通过才算 COMPLETE。
- 演示仍须通过真实代码/构建与当前服务启动、实际 JavaScript 执行、页面挂载及无致命运行错误检查。模板占位页或崩溃页面不能交付；已实现但未接路由的页面须接入真正入口。预算耗尽及模型服务不可用时也优先保存可演示版本，后续继续开发。

这取代之前“缺少凭据停止整个任务”和“完整合同未通过就禁止交付演示”的规则。单元测试仍只用于当前改动的局部诊断；不会把模拟服务验收冒充成真实外部服务成功。
