# 工作区状态同步与版本还原

生成任务通过 SSE 通知页面读取项目、任务和会话状态；SSE 不可用时，执行中的任务每 2 秒、空闲页面每 5 秒补读。可选的会话接口失败不会阻止完成消息和版本状态显示。新完成任务会刷新预览，即使其 HTML 与上一次相同。

`POST /api/projects/{id}/restore/{version}` 返回 HTTP 202 和 `restore_id`。还原在项目 worker 中执行，不依赖浏览器请求持续连接。`GET /api/projects/{id}/restore` 返回持久化进度、结果或失败原因，刷新页面后可继续显示。

客户端必须发送 `X-Atoms-Restore-Protocol: 2`。旧前端将 POST 返回值直接作为项目对象，会因受理结果不包含 `messages` 而白屏；不带协议版本的旧请求在提交任务之前被拒绝，并提示刷新。受理响应只保存任务编号，项目内容始终通过项目读取接口更新，受理不代表还原成功。

历史快照中的依赖、构建产物和运行缓存会按当前源码范围过滤，再从历史清单重建。旧版本曾收录 `.python-cache/dependency-state.json`，不能直接通过当前源码路径校验，也不能让旧缓存替代重新安装。路径穿越、密钥、私有数据等限制继续生效，历史版本记录本身不被修改。

切换版本保留全部历史版本和不可变资源对象。成功切换仅追加一条还原记录，不删除、覆盖或改写旧版本，可以继续选择较新版本切回。

还原依次执行：

1. 停止并移除旧项目容器和旧预览路由，创建新的隔离容器；校验历史源码、二进制资源、运行配置与会话对象。切换保留项目专属网络，避免断开协调器和网关造成当前受理连接丢失；应用进程和容器文件系统仍完全重建。Docker 删除容器时等待服务和浏览器子进程清理，读超时为 120 秒；其他引擎操作保留 30 秒，异常标明实际失败的操作。
2. 保存可恢复的操作前检查点，停止旧进程，并等待先前已接受的写入结束。
3. 恢复文件、文件权限、工作区配置和私有会话；移走旧依赖、构建产物及缓存状态。
4. 按历史清单准备依赖并重新构建，启动配置的服务，通过浏览器检查页面加载和 JavaScript 错误。
5. 校验源码与历史快照一致，提交新版本、预览路由和成功状态。

构建或浏览器验证失败时，恢复操作前的源码、会话、依赖和产物，不生成成功版本。worker 被中断时，下次启动先恢复检查点，再接受工作。恢复检查点失败时保留备份并阻止写入，页面明确显示失败。

新版本增加 `runtime_state`，保存自定义启动命令、文件权限以及 SQLite backup API 生成的私有会话快照。旧版本缺少这些信息时，采用版本内工作区启动配置并清除当前会话，避免继承后续失败任务的类型或验证结果。

worker 保持移除 `CAP_FOWNER` 的隔离配置。恢复项目用户拥有的文件权限时，控制进程短暂取得该文件所有权，设置历史权限后始终恢复原所有者；因此不会因无权 `chmod` 导致切换和回滚双重失败。切换成功校验全量源码摘要及历史权限；失败回滚也校验全量源码摘要后才删除恢复检查点。

新版本同时保存托管 PostgreSQL 的结构、数据、函数、约束、视图及序列状态，预览 localStorage 和按工作页标签隔离的 sessionStorage，以及 `.atoms-data` 的私有文件和 SQLite（含 WAL 提交数据）。数据库快照由独立 NOLOGIN、非超级用户角色拥有，应用角色不能读写历史快照。切换时在一个事务内恢复数据库及浏览器存储，校验结构与数据摘要；构建或预览检查不通过时，从操作前检查点一起恢复代码、私有文件、数据库和浏览器存储。新版本捕获前暂停应用进程，完成后恢复服务，避免应用写入造成文件与数据库时间点不一致。

还原请求受理前就持久化用户请求和 Mike 的一条进度消息。各阶段实时更新同一条消息，最终保存成功或失败结果；容器准备阶段、刷新、多标签和 SSE 断线均由持久化消息与补读同步。恢复消息带 `restoration` 元数据，不占用生成任务的用户消息索引，也不会显示前一轮任务的版本卡。

请求等待容器准备时仍持续读取项目、对话和还原进度。还原 POST 本身只持有删除保护锁，不持有工作区共享写锁；还原任务自行取得独占写锁，等待其他已受理写操作完成，避免请求与后台任务互相等待。

预览浏览器数据写入遵守还原锁，并要求当前存储 epoch。每次恢复变更 epoch，同时废除旧静态预览令牌，因此旧页面迟到写入不能污染恢复后的数据。原生 IndexedDB、Cookie 在当前不允许 same-origin 的预览沙箱内不可用；本机制覆盖平台提供的 localStorage/sessionStorage。外部数据库、外部服务、密钥、聊天审计记录与独立已发布站点不属于开发预览的数据快照，不因工作区还原被修改。

升级前的旧版本没有历史数据快照，不能从今天的数据重建过去。默认在改动源码或销毁容器之前拒绝完整还原，并在历史列表和对话里说明缺少快照；旧版本文件记录全部保留。可从升级后的当前状态保存新的完整版本，之后的完整版本可以反复切换。还原成功表示快照一致性和当前浏览器启动验证通过。

部署需更新后端、worker 镜像和前端。后端启动时自动创建 `project_restores`、`runtime_state` 列、项目角色权限、RLS 策略与通知触发器；正在还原的 worker 不会因镜像升级而被替换。
