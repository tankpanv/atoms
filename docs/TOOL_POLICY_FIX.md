# 工具执行策略一致性修复

项目：3bb73a02-e2f8-44e2-8e17-a5ac8dfc862a。证据见 [实际调用回放](tool-policy-verification.json)。

此前工具合同修复阻止了坏参数写入，但把所有越界都当作错误，造成额外模型往返。实际本项目四文件批次的全部字段完整，却被三文件硬限制拒绝；run_shell 的 timeout=300 在旧执行器原可限到180秒，被新增 schema 校验拒绝，并得到不相关的文件写入恢复建议。全站历史还存在15次 read_file 单页超限错误：请求13000–45000字符，工具声明未解释实际12000字符上限。

本次按参数意义处理：

- 真实命令、目标路径、源码正文、验收断言、字段类型仍严格校验，缺路径不猜测，截断 JSON 不拼接、不执行。
- 正整数 timeout 超上限自动限到180秒，limit 超上限自动限到12000字符；保留原始模型请求和 requested/effective 记录，让模型使用实际读取区间继续分页。零、负数、布尔值和字符串不当作合法整数。
- 完整的1–12文件批次可执行；1–3小文件是生成建议，不再把建议当作硬拒绝条件。所有项仍在任何写入前校验，运行时 I/O 部分成功仍需按真实结果检查。
- tool_limits.py 统一 schema、参数调整和执行的策略常量，避免改了一处、另一处还拒绝。
- 三个入口（规划、执行、复核）统一应用读取页大小调整，并保留实际参数调整结果；执行器不会因为参数调整再次调用模型或重放命令。
- 恢复提示按工具和错误类型提供。运行命令不会再得到 write_files 建议；任务更新仍要求真实成功证据及依赖完成。
- 浏览器交互动作明确要求 selector；需要 value 的动作检查字段与类型，assert_count 为非负整数，动作最多40项；带 requirement_ids 必须有 assert_*。这些字段在运行前检查，不等到浏览器副作用已经发生后才报 KeyError。
- 前端把结构化错误显示为“未执行：具体原因 + 对应恢复建议”，保留原始数据库错误供调试。历史中错误的跨工具通用提示会隐藏。拒绝的写入不再被标记为已编辑文件。
